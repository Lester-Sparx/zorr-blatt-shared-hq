# LESTER EXECUTION SURFACE POLICY R01

STATUS: PROPOSED DURABLE TEAM OPERATING LAW
AUTHORITY: SPARX
COORDINATOR: JINGO

## CORE LAW

LESTER != WORK MODE.
WORK MODE is an optional execution surface, not agent identity and not project memory.

The authoritative state of Lester's work lives in durable GitHub / Shared HQ / PR evidence.
A switch between Work and normal Chat must never restart the task or create a new Lester.

## WHEN TO USE WORK

Use Work when it materially helps with a long, multi-step task, extended tool use, deliverable creation, or sustained autonomous execution.

Do not use Work merely because the agent is LESTER.

## WHEN NORMAL CHAT IS ENOUGH

Normal Chat is preferred for:
- short repairs;
- reading current GitHub state;
- PR comments / handoffs;
- QC follow-ups;
- narrowly scoped implementation steps supported by available tools;
- coordination with JINGO and DUNCAN.

## TRANSITION PROTOCOL

If Work becomes unavailable, hits limits, or is inconvenient:

1. Open a new normal Chat.
2. Send exactly: `LESTER, RESUME FROM GITHUB.`
3. Lester loads Shared HQ + active PR + exact HEAD + CI + latest JINGO/DUNCAN handoff.
4. Lester determines ACTIVE / WAITING / BLOCKED / READY.
5. If ACTIVE, continue from the exact durable candidate. Do not restart.

No manual task packet from SPARX should be required when durable state is healthy.

## DECISION RULE

WORK MODE = OPTIONAL ACCELERATOR.
GITHUB / SHARED HQ = CONTINUITY LAYER.
LESTER ROLE = PERSISTENT LOGICAL IDENTITY.

If Work provides no material advantage for the current task, stay in normal Chat.
