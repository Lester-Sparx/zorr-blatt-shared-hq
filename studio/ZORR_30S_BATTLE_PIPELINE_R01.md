# ZORR BLATT — 30s BATTLE PRODUCTION PIPELINE R01

STATUS = OWNER-AUTHORIZED CURRENT PRODUCTION STANDARD
MASTER ROUTER = issue #274
TARGET = repeatable ~30-second vertical anime battle shorts for social audience growth

## 1. ONE LOOP ONLY

Every production follows the same path:

`SCENARIO -> STORYBOARD/LAYOUT -> KEY POSES + BREAKDOWNS -> RIFE INBETWEENS -> DAVINCI RESOLVE/FUSION -> SOUND/QC -> RELEASE -> LEARN -> NEXT SHORT`

Do not create parallel production architectures. Do not resurrect the old 10s-first duration gate. A 30-second short may be internally segmented into 3 x ~10-second blocks only for planning and assembly; production continues through the whole short unless a real blocker stops it.

## 2. PRODUCT TARGET

Current default short:
- vertical 9:16;
- approximately 30 seconds;
- K1 = strong humanoid character;
- K2 = dangerous creature/monster;
- immediate readable confrontation;
- hook/scroll-stop within ~2 seconds;
- silent conflict readability within ~3–5 seconds;
- several short action bursts;
- clear initiative shift / escalation / reversal;
- 2–4 iconic fashion or psychedelic poses;
- one memorable payoff/cliffhanger/replay beat;
- strong negative space, silhouettes, value masses and graphic composition.

Transferable study principles may include:
- BLEACH: negative space, restraint, value hierarchy, power through economy;
- Afro Samurai: quiet-before-burst timing, lethal economy, dust/impact physicality;
- JoJo: fashion pose language, unusual body plasticity, aggressive composition, graphic freeze beats.

These are study principles only. Never copy specific scenes, frames, characters or exact styles.

## 3. LIMITED ANIMATION IS THE BASE

The base language is:

`POSE -> HOLD -> BURST -> POSE -> CUT -> HOLD`

Most of the short should be carried by:
- strong key poses;
- deliberate exposure/holds;
- hard cuts;
- reframing / push / pan;
- speed lines / dust / impact FX;
- graphic value/color changes;
- sound timing;
- fashion-driven silhouettes.

Smoothness is selective, not continuous.

## 4. STAGE P01 — SCENARIO

Input:
- character/creature/location references if provided;
- current social/action target;
- current hardware/tool limits.

Required output:
- title/logline/conflict/emotional result;
- exact 0:00–0:30 timeline;
- hook <=2s;
- silent readability <=3–5s;
- full physical action script;
- shot map;
- location pack;
- K1/K2 reference needs;
- key-pose list;
- semantic breakdown list;
- exact RIFE-safe windows and NO-RIFE zones;
- VFX/SFX/music/silence/edit rhythm;
- asset count;
- first build order;
- do-not-make-yet list;
- 10-pass social/action audit.

Scenario quality gate:
1. hook;
2. silent readability;
3. action density / no tempo holes;
4. escalation/reversal;
5. payoff/replay;
6. fashion/beauty/iconic pose quality;
7. creature threat clarity;
8. limited-animation feasibility;
9. RIFE safety;
10. overall social attraction.

If a critical item fails, rewrite before handoff.

## 5. STAGE P02 — STORYBOARD / LAYOUT

Goal: convert the approved scenario into exact visual beats before generating expensive frames.

For every shot define:
- shot ID;
- timecode and exact 24fps frame range;
- shot size;
- camera height / angle / movement;
- screen direction / action axis;
- K1/K2 positions;
- negative space and value masses;
- background/location frame;
- hero/key pose;
- transition;
- shot function;
- VFX/SFX cue;
- production route.

Storyboard rule:
- do not beautify unclear staging;
- if the action cannot be understood from silhouettes and arrows/poses, fix layout before key generation;
- preserve 9:16 safe composition;
- use payoff location elements only when they strengthen escalation, not in every shot.

## 6. STAGE P03 — KEY POSES + SEMANTIC BREAKDOWNS

Generate only the frames that carry meaning.

KEY POSE = important action/acting state/extreme.
BREAKDOWN = designed intermediate state that controls path, arc, body rotation, overlap, contact and spacing.

Priority:
`IDENTITY + SILHOUETTE + ACTION READABILITY > SMOOTHNESS`

For each adjacent state classify change:

### SMALL CHANGE
Direct RIFE candidate.
Examples:
- hand to weapon;
- micro head/torso turn;
- short step;
- short lunge segment;
- recoil/settle;
- simple limb arc.

### MEDIUM CHANGE
Create at least one semantic breakdown first. RIFE only on smaller sub-intervals.
Examples:
- moderate torso turn;
- dodge with plane change;
- controlled weapon-plane shift;
- simple pass-by motion.

### LARGE CHANGE / NO-RIFE
Do not directly interpolate.
Examples:
- major rotation;
- strong occlusion;
- newly revealed body/form;
- contact/grappling;
- impact frame;
- large perspective change;
- transformation;
- cut.

Never interpolate across a cut.

## 7. STAGE P04 — RIFE / FLOWFRAMES

RIFE exists to add selective smoothness to already-correct animation logic.
It does not invent choreography.

For every RIFE interval record:
- source frame A;
- source frame B;
- intended output count;
- exact fill-frame range;
- change class;
- reason the interval is safe;
- expected artifacts;
- fallback if it fails.

Reject locally if RIFE produces:
- doubled limbs;
- face/identity drift;
- warped suit/hair/weapon;
- wrong overlap;
- topology melt;
- false contact;
- unstable smoke/creature ribbons.

Accepted keys remain frozen. Replace only the bad sub-interval.

HOME-PC baseline:
- Ryzen 5 7535HS;
- 16 GB RAM;
- RTX 3050 Laptop 4 GB VRAM.

Critical path must remain workable without heavy local video models, Seedance or paid cloud services.

## 8. STAGE P05 — DAVINCI RESOLVE / FUSION

Resolve/Fusion is the assembly and finish environment.

Use it for:
- exact 24fps timeline;
- drawing exposure on ones/twos/threes/holds;
- cuts;
- pan/zoom/reframe;
- parallax;
- masks/layers;
- dust/smoke/speed accents;
- impact flashes;
- shake;
- value/color treatment;
- motion blur only when it helps;
- sound design;
- music placement;
- final rhythm.

Do not use Fusion to hide broken staging or bad keys. Fix the upstream frame when the upstream frame is wrong.

## 9. STAGE P06 — QC / RELEASE

Required checks:
- exact duration / FPS / frame count;
- hook works at normal scroll speed;
- conflict reads muted;
- no tempo holes;
- screen direction is coherent;
- K1/K2 identity survives;
- weapon/wardrobe/location continuity survives;
- no unsafe RIFE artifacts;
- impact/payoff reads clearly;
- 9:16 safe composition;
- sound supports, not rescues, the scene;
- export is technically valid for the target platform.

Release is the real learning boundary. A pretty test file is not the same as a released/evaluated short.

## 10. STAGE P07 — LEARN / NEXT

After each released or fully evaluated short, persist only useful production lessons:
- what held attention;
- where viewers could lose the action;
- which pose/composition was strongest;
- which asset cost too much;
- which RIFE interval worked/failed and why;
- which Resolve/Fusion trick gave high value cheaply;
- which sound beat mattered;
- what should be changed in the next short.

Apply 1–3 concrete improvements to the next production.

Learning rule:
`PRODUCTION -> EVIDENCE -> SMALL LESSON -> NEXT SHORT`

Do not create endless study projects detached from a current short.

## 11. HANDOFF CONTRACT

A scenario DOCX/ZIP is an execution input.
A new production chat must:
1. perform only the minimum durable authority check needed to detect contradiction;
2. read the handoff `START_HERE` / first unfinished step;
3. immediately execute that step;
4. continue through the pipeline without asking OWNER to type `continue` between obvious stages;
5. stop only on a real blocker;
6. never redesign an approved handoff without explicit OWNER command or proven contradiction.

Bootstrap is a gate, not the task.
Status is not the product.

## 12. STANDARD PROJECT FOLDERS

For each short:
- `SCENARIO_`
- `LOC_`
- `K1_`
- `K2_`
- `SHOT_`
- `RIFE_`
- `AUDIO_`
- `VFX_`
- `MASTER_`

Every file name should identify the short, shot/state and version clearly enough for another chat to continue without guessing.

## 13. MASTER RULE

Always return to this loop:

`SCENARIO -> STORYBOARD -> KEYS/BREAKDOWNS -> RIFE -> DAVINCI -> RELEASE -> LEARN -> NEXT`

If work does not advance one of these stages or remove a real blocker between them, it is probably not the current priority.
